The **AI-Powered Study Assistant** is a Retrieval-Augmented Generation (RAG) system built to help users interact with their study materials through natural language questions, instead of manually searching through documents.

**How it works:** a user's document (PDF or TXT) is loaded and split into smaller overlapping text chunks using `RecursiveCharacterTextSplitter`. Each chunk is converted into a 384-dimensional vector using the `all-MiniLM-L6-v2` embedding model, and all these vectors are stored in a FAISS vector database for fast similarity search. When a question is asked, it's embedded the same way, and the system retrieves the top-3 most semantically similar chunks from the document. These retrieved chunks are combined with the question into a single prompt, which is sent to a locally-running LLM (`llama3.1:8b`, via Ollama) that generates a detailed answer grounded strictly in the retrieved content — explicitly avoiding hallucination by stating "I don't know" when the document doesn't contain the answer.

**Beyond the core pipeline**, the project includes two optimization experiments to justify design choices with real evidence rather than assumptions: a **chunking comparison** (testing baseline, smaller, and larger chunk configurations, each with its own retriever and real generated answers) and a **hybrid retrieval system** combining BM25 keyword search with FAISS vector search via `EnsembleRetriever`, to catch exact-term matches that pure semantic search might miss. The system also supports **conversation memory** through a sliding window (retaining the last 3 exchanges), allowing natural follow-up questions without repeating context, and a **flexible document loader** that lets any new PDF or TXT file be loaded and fully re-indexed with a single function call (`load_new_document()`).

**Validation** was done through a multi-question test set — including one deliberately unrelated question — to confirm the system reliably answers relevant questions while correctly declining to answer when information isn't present in the document. A consolidated **system metrics report** documents the final configuration: chunking profile, embedding dimensions, vector store details, retrieval strategies tested, and LLM setup — providing a transparent, reproducible summary of the entire system's design.

**The end goal** is a Streamlit-based web application where users can upload any document and get an interactive, chat-style Q&A experience — reducing manual searching, improving study efficiency, and demonstrating a practical, locally-run RAG architecture built entirely without external paid APIs.
